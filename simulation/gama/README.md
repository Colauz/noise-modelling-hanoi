# GAMA simulation — noise scenarios

**Model:** `hanoi_noise.gaml` · **Inputs:** `inputs/` (per-zone roads, buildings,
noise grid, measurements, construction sites, fleet and physical parameters).

## Running it

Open `hanoi_noise.gaml` in [GAMA](https://gama-platform.org) ≥ 2025.6 and run the
`hanoi_noise_sim` experiment. Everything it needs is in `inputs/`, which is
versioned on purpose: **a GAMA user with no Python environment can clone the
repository and run the model**.

Headless, three cycles, as used to verify the model after the restructuring:

```bash
gama-headless.sh -xml hanoi_noise_sim simulation/gama/hanoi_noise.gaml params.xml
# set finalStep in params.xml, then:
gama-headless.sh params.xml out/
```

Inputs are regenerated by `python3 scripts/07_export_gama_inputs.py` — the single
producer. There used to be two, which is how the retracted Bach Khoa grid
survived as long as it did.

## The design decision: receiver agents, not emitter agents

GAMA is an agent-based platform, and there are two ways to put agents in it. They
do not cost the same in data.

- **Emitter agents (motorcycles, cars)** need real per-street flows, fleet
  composition, speeds and signal cycles. We have none of that for Hanoi, so the
  simulation would be neither calibratable nor verifiable. **Rejected** — see below.
- **Receiver agents (residents, pedestrians)** move through the area and
  accumulate a **noise dose** as they cross our map. The input is our own
  measured-and-validated map; nothing is invented. **This is our agent layer.**

The result is a genuine agent-based simulation — mobile agents, behaviours, an
indicator emerging at population level — calibrated by our data, producing what a
map alone cannot: **people's exposure**.

## Tiers

### Tier 1 — interactive map and traffic slider — **implemented**
1. Load roads and buildings.
2. Display the coloured noise grid from the exported inputs.
3. Interactive `traffic_multiplier` (×0.2 to ×3): doubling traffic adds 3 dB,
   applied **only to the traffic share of the energy** (see below).
4. Live indicator: share of the area above the QCVN 26:2010 daytime value.

### Tier 2 — exposed pedestrian agents — **not implemented**
- N agents with simple daily journeys over the road network.
- Each accumulates a dose: level of the cell crossed × time spent.
- Indicators: distribution of daily doses, mean exposure by journey type.

### Tier 3 — scenarios — **partially implemented**
- Pedestrianisation: ×0.2 on selected streets.
- Peak hour ×1.5.

## Two physics corrections that changed the answers

**Scenario energy is decomposed.** `10·log10(k)` and any mitigation apply only to
the **traffic share** of the energy, not to the total, with the background term
taken from the same kernel the model uses. Before this correction the model
claimed −7.0 dB of zone mean for pedestrianisation; the correct figure is
**−3.5 dB**. The benefit had been overstated by a factor of two. Invariant
checked: at k = 1 with no mitigation, the simulated map equals the predicted map.

**Measured flow applies only to the observed corridor.** Vehicles were created on
`one_of(Road)`, spreading one point's measured flow uniformly over the 673 streets
of a zone that extends 400 m beyond the survey envelope — 0.076 vehicles per
street, leaving the Hoan Kiem lake loop empty 92 % of the time although every
video was filmed there. Flow is now injected only on streets within `FLOW_RADIUS`
(150 m) of a measurement point. It is also the more honest choice: we measured
nothing 400 m from the lake, so we inject nothing there.

## Why individual vehicles are not simulated

1. **No data to calibrate them.** Per-street flows, modal shares, speeds, signal
   cycles: we have none. Every simulated motorcycle would carry an invented
   acoustic power — apparent precision built on guessed parameters.
2. **No data to validate them.** Our 363 measurements validate a map of mean
   levels, not a microscopic traffic dynamic. An unverifiable simulation adds
   nothing scientific.
3. **The first-order effect is already captured.** Aggregate flow noise follows
   ~10·log10(flow), which tier 1 applies exactly. Emitter agents would add
   instantaneous variance — individual passes, horns — that our question does not
   need.
4. **Cost against benefit.** Tiers 1 and 2 are days of work. A calibrated agent
   traffic layer is weeks, plus a counting campaign.
5. **Our credibility comes from the measurements.** The chain real data → validated
   model → calibrated map → simulated exposure is verifiable end to end. An
   uncalibrated traffic layer would break that thread.

To be mentioned in the paper as **future work**: coupling with traffic count data
(sensors, video) to add emitter agents.
